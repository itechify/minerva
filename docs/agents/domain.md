# Domain Docs

Before exploring, read the root `GLOSSARY.md` and the ADRs in `docs/adr/` that touch your area. This repo is single-context.

Use the glossary's terms in issues, proposals, hypotheses and test names. Reconsider unfamiliar terms; note real vocabulary gaps for `/domain-modeling`.

Flag any conflict with an existing ADR explicitly, naming the decision and why it should be reopened.
